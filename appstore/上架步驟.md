# 上架 App Store 步驟

沒有 Mac 也能上架：iOS App 由 GitHub 的雲端 Mac 打包並上傳。下面是只能你本人做的部分，照順序做一次就好。

需要準備：已加入 Apple Developer Program 的 Apple 帳號、這個 GitHub 專案的管理權限。

## 1. 註冊 Bundle ID

1. 到 [Certificates, Identifiers & Profiles](https://developer.apple.com/account/resources/identifiers/list)。
2. 按 Identifiers 旁邊的「+」→ 選 **App IDs** → **App** → Continue。
3. Description 填 `一指連鎖`（只能英數字的話填 `One Tap Chain`），Bundle ID 選 **Explicit**，填 `com.hankhsu.onetapchain`。
4. Capabilities 都不用勾，按 Continue → Register。

## 2. 在 App Store Connect 建立 App

1. 到 [App Store Connect](https://appstoreconnect.apple.com/apps) →「App」→ 左上角「+」→「新增 App」。
2. 平台勾 **iOS**；名稱 `一指連鎖`；主要語言 **繁體中文**；套件識別碼選剛才的 `com.hankhsu.onetapchain`；SKU 填 `onetapchain`；使用者存取權選「完整存取權」。
3. 名稱被別人用掉的話會在這一步被擋，換一個再告訴我。

## 3. 建立 App Store Connect API 金鑰

雲端 Mac 用這把金鑰代替你登入：自動建立發佈憑證、簽署 App、上傳。

1. 直接打開 https://appstoreconnect.apple.com/access/integrations/api ，或從 App Store Connect 首頁點「使用者和存取權限」→ 上方的「整合」分頁 → 左側「App Store Connect API」→「團隊金鑰」。英文介面是 Users and Access → Integrations → App Store Connect API → Team Keys。第一次用要先按「要求存取權限」（Request Access）並同意條款，只有帳號持有人看得到這個按鈕。
2. 按「+」產生金鑰：名稱填 `GitHub Actions`，存取權選 **管理（Admin）**（自動建立發佈憑證需要這個權限）。
3. 下載 `AuthKey_XXXXXXXXXX.p8`。**只能下載一次**，請收好，不要傳給別人或放進專案。
4. 記下這把金鑰的 **Key ID**，以及頁面上方的 **Issuer ID**。

## 4. 查 Team ID

到 [Apple 開發者帳號的會員資格](https://developer.apple.com/account#MembershipDetailsCard)，「Team ID」是 10 個字元的英數字。

## 5. 把金鑰放進 GitHub Secrets

1. 到 [專案的 Actions Secrets 設定](https://github.com/HankHsu1969/one-tap-chain/settings/secrets/actions) → New repository secret。
2. 新增以下四個（名稱要完全一樣）：

| 名稱 | 內容 |
| --- | --- |
| `APPLE_TEAM_ID` | 第 4 步的 Team ID |
| `APPSTORE_API_KEY_ID` | 第 3 步的 Key ID |
| `APPSTORE_API_ISSUER_ID` | 第 3 步的 Issuer ID |
| `APPSTORE_API_PRIVATE_KEY` | 用記事本打開 .p8 檔，整份內容（含 `-----BEGIN PRIVATE KEY-----` 那兩行）貼上 |

Secrets 存進去之後誰都看不到內容，包括你自己和 Claude。

## 6. 執行雲端打包

1. 到專案的 [Actions](https://github.com/HankHsu1969/one-tap-chain/actions) → 左邊選「iOS 打包上傳」→ 右邊「Run workflow」→ 分支選 `main` → Run workflow。
2. 大約 10–20 分鐘跑完。打勾代表已經上傳；打叉的話點進去，把出錯的那段紀錄貼給 Claude 修。
3. 上傳後再等 10–30 分鐘，App Store Connect 的「TestFlight」分頁會出現這個組建。

想先在自己的 iPhone 上試玩：TestFlight 分頁 →「內部測試」→ 新增群組並把自己加進去，再用 iPhone 的 TestFlight App 安裝。

## 7. 填商店頁面並送審

到 App Store Connect 的 App 頁面，照 `appstore/商店資料.md` 填：

1. **App 資訊**：副標題、類別、隱私權政策網址、年齡分級問卷。
2. **價格與供應狀況**：免費、要上架的國家或地區。
3. **App 隱私權**：選「不收集資料」並發佈。
4. **1.0 版本頁**：上傳 `appstore/screenshots/` 的五張截圖，填促銷文字、描述、關鍵字、支援網址、版權、審查備註；「組建」選第 6 步上傳的那一個。
5. 右上角「新增以供審查」→「提交審查」。

審查通常 1–2 天。被退件的話，把 Apple 的說明貼給 Claude 一起處理。

## 之後要更新版本

1. 改完遊戲、推上 `main`。
2. 要換版號（例如 1.0 → 1.1）時，把 `ios/App/App.xcodeproj/project.pbxproj` 裡兩處 `MARKETING_VERSION` 改掉。只是重新上傳同一版的話不用改，組建編號會自動加一。
3. 重跑第 6 步，再到 App Store Connect 建立新版本、選新組建、送審。
